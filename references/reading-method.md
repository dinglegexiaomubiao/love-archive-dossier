# 精读方法：怎么从十万条里找出真正的节点

核心原则：**不要通读，用三个筛子把十几万条缩到十几个窗口。**

十万条全喂给模型有两个问题：单次上下文装不下（要切成十几片），切完之后全局结构就丢了——你看不出「2 月 15 日是个拐点」，因为每片都只是局部。

所以顺序必须是：**先统计出骨架，再精读填血肉。** 反过来做，一定偏。

---

## 筛子一：拐点（找「那天发生了什么」）

```bash
python scripts/collect.py -c config.toml spikes
```

输出三类东西：

| 类型 | 含义 | 怎么用 |
|---|---|---|
| 突增日 | 当日量 ≥ 前 7 日均值 × 2.5，且绝对增量 ≥ 50 | 每个突增日背后都有一个事件，去原文看那天 |
| 月度下滑拐点 | 环比 ≤ 0.75 且减少 ≥ 500 | 退潮通常是渐进的，这是唯一能抓到的信号 |
| 完全空白期 | 连续 ≥ 7 天没有任何消息 | 空白往往比热聊更有信息量 |

**为什么必须按天而不能按月？**
按月看，472 条涨到 2,554 条只是「高一些」；按天看，才能发现 2 月 14 日是 28 条、2 月 15 日是 217 条——中间是断崖，对应一个具体事件。

**为什么突增要加「绝对增量」门槛？**
低基数时期会误报：日均 8 条的阶段，一天 80 条就是 10 倍。但那只是「某天多聊了几句」，撑不起一个时代。

## 筛子二：关键词（找「那句话在哪」）

```bash
python scripts/collect.py -c config.toml grep "算了|不理你|受不了" 2022-01-01 2023-03-01
python scripts/collect.py -c config.toml grep "在一起|做我女朋友|喜欢你" 2020-01-01 2023-12-31
```

关键词按主题分组（config 里已配好六组）：

| 组 | 找什么 |
|---|---|
| 关系确认 | 有没有正式命名过这段关系 |
| 思念 | 想你的表达密度与时机 |
| 见面 | 异地成本、谁去找谁 |
| 亲密 | 身体距离的语言 |
| 冲突 | 关门方式、道歉方式 |
| 家庭 | 家人出场的地方（往往藏着价值观） |
| 礼物 | 仪式感与实用主义的碰撞 |

**关键：必须看上下文。**
单看一句「算了」说明不了什么，可能是真的放弃、也可能是撒娇。脚本默认输出前后 2 条，一定要连着读。

判断「关门」还是「撒娇」的简易标准：
- 后面紧跟别的轻松话题 → 撒娇（她在给台阶）
- 后面是长时间沉默或「我看书去了」→ 真关门

## 筛子三：时间窗（把整段读完）

```bash
python scripts/collect.py -c config.toml dump 2022-02-15 2022-02-16
python scripts/collect.py -c config.toml dump 2023-02-24 2023-02-25
```

单日 300–1,500 条是可以完整读完的量。**必读的四个窗口**：

1. **关系的第一个转折点**（通常是最早的突增日）
2. **峰值期里的普通一天**——不是最热闹那天，是「没有事件的那天」。日常质感在普通日子里，不在高光里。
3. **退潮的起点**（月度下滑拐点那个月的前后几天）
4. **最后一天**——最后几句的措辞往往解释了一切

读整段时，注意三样东西：

- **谁说最后一句**（谁先结束对话，谁掌握节奏）
- **消息长度的变化**（从长段变短句，通常是激情消退的第一个信号）
- **有没有「未回应的话题」**（一方提起某事，另一方岔开了——这些岔开的话题累积起来就是问题）

## 精读产出：事件卡

每读完一个窗口，产出一张事件卡：

```markdown
### 事件 NN · 标题（日期）

**原话**
> 引用一
> 引用二

**读法**：表面发生什么 / 实际在发生什么

**后续**：后来有没有被提起、印证或反转
```

事件卡的三条硬规则：

1. **原文必须准确**。不要转述，不要润色。
2. **读法要区分表面与实质**。她说「你想过寄过来会碎多少吗」（表面是物流问题），实质是「第一次送东西你怎么这么随便」。
3. **后续比读法更重要**。一个事件如果后面再没被提起，说明它没留下痕迹；如果被反复提起，说明它是旧账的一部分。

---

## 找「反复出现的模式」

单个事件是故事，重复出现的事件才是性格。

方法：把事件卡按「模式」归类，而不是按时间排。例如：

| 模式 | 出现次数 | 典型表现 |
|---|---|---|
| 用玩笑接重话 | 多次 | 她说「来我床上吗」，他回「阳台门帮我打开一下」 |
| 先解释后共情 | 多次 | 每次冲突的第一反应都是澄清「我不是那个意思」 |
| 关门试探 | 231 次 | 「算了」，然后等对方猜 |

归类之后，第 5、6 节的画像和动力学就有骨架了。

## 常见误读

| 误读 | 纠正方法 |
|---|---|
| 「她话更多 = 她更投入」 | 看平均字数与主动开场数。消息多可能只是短句多 |
| 「她只要情绪不要道理」 | 数一下双方的解释性表达（因为/所以/其实），实测常常相反 |
| 「他不撤回 = 他笃定」 | 先确认撤回记录的归属。系统消息「你撤回了一条消息」指的是本人 |
| 「吵架少 = 关系好」 | 也可能是不吵、但也不解决。看问题有没有留下 |
| 「最后一句很冷淡 = 感情早没了」 | 看这句之前 30 分钟说了什么。收尾的语气和关系的温度常常无关 |

## 时间预算参考

| 数据量 | 统计 | 精读 | 写档案 |
|---|---|---|---|
| 1 万条 | 1 分钟 | 30 分钟 | 1 小时 |
| 5 万条 | 1 分钟 | 1 小时 | 2 小时 |
| 18 万条 | 1 分钟 | 2 小时 | 3 小时 |

精读占比应该低于全文的 2%。如果发现自己在通读，说明筛子没设好。
