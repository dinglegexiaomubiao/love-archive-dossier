# 数据陷阱清单

**做之前必读。** 下面每一条都是实际踩过的坑，踩了会得出相反的结论。

---

## 1. 撤回归属：最容易搞错的一项

数据里的撤回记录长这样：

```json
{"sender": "系统", "type": "撤回", "content": "\"对方\" 撤回了一条消息"}
{"sender": "系统", "type": "撤回", "content": "你撤回了一条消息"}
```

**坑**：`"你撤回了一条消息"` 里的「你」指的是**数据所有者本人**，不是对方。如果不做归属判断、或者把它当成未知，会出现「我方撤回 1 次」这种离谱数字（实际可能是 866 次）。

**正确做法**：

```python
def owner(content: str) -> str:
    if "你撤回" in content:
        return "me"
    if "撤回了一条消息" in content:
        return "other"
    return "?"
```

**为什么重要**：撤回归属搞反，会导致「谁在意措辞」「谁敢于冒险」这两个结论完全反向。本 skill 的实测案例里，本人撤回次数是对方的 2.9 倍，如果按错误归属写，就会得出「对方反复删自己话，本人从不」的错误画像。

---

## 2. 撤回的两种用法，要靠「补发率」区分

同样是撤回，心理机制可能完全相反：

| 类型 | 特征 | 含义 |
|---|---|---|
| 改句子 | 撤回后 2 分钟内有补发 | 「重来一次」，内容焦虑 |
| 抹掉 | 撤回后不再补发 | 「没发生过」，暴露焦虑 |

统计方法：撤回后 120 秒内，同一人是否发了新的文本消息。

**不要只看次数**。302 次撤回 0 补发，和 866 次撤回 78% 补发，是两种完全不同的性格。

---

## 3. 阶段切分：边界排序不能用「倍数」

**坑**：用「当日量 / 前 7 日均值」的倍数排序，会选出低基数时期的波动。日均 10 条的时期，一天 200 条就是 20 倍；而日均 600 条的时期，涨到 1200 条只有 2 倍。结果真拐点被挤掉，切出几十个一天、三天的碎片。

**正确做法**：用**绝对变化量**排序（`delta = 当日量 - 前 7 日均值`，或月度环比的实际减少量）。

**同时**：切完要合并短于 14 天的碎段，并限制总段数（10 段左右）。人读得懂的是 6–10 个阶段，不是 24 个。

---

## 4. 阶段标签：表达「方向」而不是「高低」

**坑**：用「相对全期日均」给阶段贴「高涨/平稳/低频」标签。退潮期的绝对量往往仍高于全期平均（例如日均 345 vs 全期 144），于是退潮段被标成「高涨」——**故事读反了**。

**正确做法**：标签表达**相对上一段**的变化方向：
- 变化 ≥ 1.5 倍 → 升温
- ≤ 0.7 倍 → 退潮
- 其余 → 平稳

这样叙事才对：「起步 → 升温 → 平稳 → 退潮 → 退潮」。

---

## 5. 退潮抓不到，因为它是渐进的

突变检测只能抓「突然变多」。真实的分手前兆通常是连续几个月每月少一点，没有单日断崖。

**必须单独加一层**：月度环比检测（环比 ≤ 0.75 且绝对减少 ≥ 500）。否则你会看到「2022-06 到 2023-02 是一大段平稳的 247 天」，把整个退潮期吞掉。

---

## 6. 只统计文本 = 漏掉一半真相

**坑**：只分析文本消息。实际上消息类型里，表情、语音、撤回、引用这四类最能暴露模式：

| 类型 | 暴露什么 |
|---|---|
| 语音 | 谁愿意用「不可撤回」的表达。语音是最难伪装的通道 |
| 表情 | 谁把语气外包给了表情包 |
| 引用 | 谁在逐条回应（工程师式沟通），谁在整体回应 |
| 撤回 | 见第 1、2 条 |

**典型发现**：语音数量差异可能达到 19 倍，而这个数字比「说了几次喜欢你」更能说明谁在冒险。

**注意**：语音只有条数，没有内容，也没有时长。不要凭空写「她语音里带着笑意」。

---

## 7. 「她要情绪不要道理」是个常见误判

**坑**：看到「我只是跟你表述我的感受」就下结论「她只要情绪价值」。

**验证方法**：统计双方的**解释性表达**（因为/所以/其实/意思是/逻辑）。实测案例里，被指为「只要情绪」的那一方，解释性表达反而更多（745 vs 421）。

**正确表述**：她要的不是「你别讲理」，是「**你先把我放在道理前面**」。顺序问题，不是立场问题。

这个区别决定了反思清单有没有用——如果理解成「不要讲理」，那学到的对策就是错的。

---

## 8. 关系是否被命名，要专门查

**坑**：默认「每天聊 700 条 = 在谈恋爱」，不做验证。

**做法**：全库检索「在一起 / 做我女朋友 / 男朋友 / 女朋友 / 表白 / 答应我」，看有没有确认性表述。

**可能的结果**：全库 0 次确认，但对方在冲突中自称「我现在只是你的女朋友」。这种情况下，档案要如实写：「身份在她的认知里存在，在语言里从未出现」——这是一个重要发现，不是数据缺失。

---

## 9. 时间戳单位可能是毫秒

有些导出工具给的是毫秒（13 位），有些是秒（10 位）。混用会让时间线整体错位到 1970 年或 5 万年后的。

**判断**：`if value > 1e11: value //= 1000`（1e11 秒 ≈ 公元 5138 年，安全阈值）。

---

## 10. 合并转发不展开，统计全错

一次合并转发里可能包含 20 条原始对话。不展开的话，这 20 条会被算成 1 条，导致：消息量失真、高峰日检测失败、时间线出现假的「空洞」。

**做法**：展开 `forwarded_messages` 里的每一条，按各自的 `timestamp` 和 `sender` 计入。展开后要注意：转发里的 `sender` 可能是第三人（群聊里的其他成员），统计双方对比时要排除。

---

## 11. 口径不一致，跨档案就不可比

**坑**：第一次用 `session_gap_hours = 4`，第二次改成 2，然后比较「对话场次」——毫无意义。

**做法**：把口径写进 config 模板，每段关系都用同一份，只改 `path` / `me` / `other`。三个必须固定：

- `session_gap_hours`
- `reply_delay_max_hours`
- `[emotion]` 正负词表

---

## 12. 别给关系下「爱与不爱」的定论

这是边界问题，不是技术问题。

档案能说的是：他做了什么、她做了什么、两者撞在一起产生了什么。
档案不能说的是：谁更爱谁、谁对谁错、如果当初怎样会不会不一样。

看到「她其实不够爱你」这类句子，删掉。它不是数据能支撑的结论，而且对读者有害。

---

## 13. 敏感度：最后阶段最容易写残忍

关系结束的档案里，倒数几幕往往充满攻击性的话。写的时候：

- 写事实，不加形容词（不写「她冷冷地说」）
- 点评挪到「归因」一节，并且必须包含「不是任何人的责任」那一行
- 如果当事人表达了愧疚，档案里要明确指出哪些责任不该由他背

**这不是讨好，是准确。** 把所有责任归给一个人，是不准确的归因，也是有害的结论。

---

## 14. 合并转发里的第三方 sender 会伪造关系起点（实测）

第 10 条说「转发里的 sender 可能是第三人，统计双方对比时要排除」，但**光在心里记住没用**。
`load()` 展开 `forwarded_messages` 后会把这些消息当作正常记录塞进 `recs`，于是：

| 被污染的东西 | 表现 |
|---|---|
| `sessions.initiator` | 出现十几个陌生名字（实测某关系数据里有 甲 / 乙 / 丙 等 15 个第三方名字） |
| `monthly` / `yearly` | 每个月都混进一堆第三方名字，无法读出双方节奏 |
| **`meta.first`** | 被拉到几年前（实测从真实的相识日，被伪造成数年前） |
| `days` / `per_day` | 跟着崩坏：2,506 天 / 日均 22.5 → 真实是 266 天 / 日均 207.6 |
| `phases` | 切出一个长达 2,287 天、日均 4.1 条的假「起步期」 |

**为什么致命**：它让一段 9 个月的相亲关系看起来像一段拖了 7 年的长跑，后面所有阶段、拐点、衰减判断全跟着错。

**做法**（`collect.py` 的 `strict_parties`，默认开启）：
在 `load()` 末尾只保留 `me` / `other` / `系统` 三方。系统消息必须留着——撤回归属判定靠它。
`me/other` 未配置时先按频次自动推断，再过滤。

```toml
[stats]
strict_parties = true    # 默认；设 false 可恢复旧行为（不建议）
```

**验证口径**：跑完看一眼 `cmd_analyze` 打印的「双方：」和 `开场：`——若开场里有陌生名字，或起止日期明显早于你们认识的时间，就是被污染了。

**注意**：`detect_conflicts.py` 复用同一个 `load()`，因此同样受这个开关保护；关掉过滤会产生大量假冲突段。

## 15. 引用消息会污染词频与情感（实测）

引用消息的 `content` 会把被引用原文一起带进来。若引用的是小程序卡片 / 名片 / 分享链接，
正文里会夹带 `appmsg` / `aeskey` / `wxid_` 等 XML 垃圾，分词后变成高频「词」，
SnowNLP 情感也会被长段噪声拉偏（实测一份 5.5 万条记录里有 7,208 条引用消息）。

**做法**：词频与情感只取说话人自己的文本——按引用标记截断：

```python
own_text = content.split("[↩", 1)[0]   # 各导出工具的引用标记可能不同，先抽样确认
```

**别用正则全文清洗**：会把正常聊天里的括号、英文、链接一起误删，反而损失语料。

## 16. 坏数据页会让一次导出全盘失败（微信 4.x 实测）

微信本机库逐页 HMAC 校验时，可能存在一个固定损坏页（实测 `message_0.db` 第 262145 页 / 共 262960 页），
重启微信也救不回。原工具「任一页失败即全库中止」，连带其他好分片全部导不出。

**做法**：导出工具要有默认关闭的容错模式——失败页尽力解密填充并记入损坏页列表、
`integrity_check` 告警后继续、单分片异常隔离。导出后必须看验证报告 `status`。

**档案里要如实写**：损坏页占比、可能缺失的极少量消息，写进第 1 节「完整性」，不要假装数据是 100% 完整的。

---

## 17. 别把两套会话切分口径的结论混着用

同一个问题「谁更主动」，手写 3 小时间隔切分可能得出「我发起 70%」，
而项目的 `adaptive_iqr` 切分得出「对方发起略多」。两者都对，只是**口径不同**。

**做法**：档案只采用 `config.toml` 里固定的 `session_gap_hours`（默认 4）那一套；
若引用了其他工具的结论，必须在括号内注明其口径，且不要把两个数字写进同一张可比总表。

---

## 18. 「零冲突」多半是没跑检测器，不是真的没吵（实测）

一段 18 万条、被手工档案写成「零冷战、极少冲突」的关系，用 `detect_conflicts.py` 同一口径重跑，
实得 **46 段冲突**（强冲突 11 段）。原判断的来源有两个偏差：

| 偏差 | 说明 |
|---|---|
| 把「不冷处理」当成「不吵」 | 那段确实吵完就过、几乎不冷战，但吵的次数并不少 |
| 情绪词泡在第三方话题里 | 大量「无语死了」是在吐槽室友/学校/家人，人工翻到时容易一并归为「日常闲聊」 |

**做法**：判断「有没有冲突 / 冲突多不多」必须用统一口径的检测器跑，且跨档案比较时四个参数必须一致：
同一套冲突词分层表、`gap`、`min_intensity`、`strict_parties`。

**还要看强度不看段数**（实测）：两段段数接近（46 vs 52），但单场最高强度 56 vs 273、总强度 549 vs 1014，
性质完全不同：一段的高强度日是「深夜交换伤口」（互相袒露），另一段是「删前任双标」（互相举证）。
只写「都有 50 场左右吵架」会把两段讲成同一段关系。

## 19. 成册时把深描结论回写进画像，否则模块彼此孤立

合并多个 HTML 时最容易犯的错是「拼完就完」：画像卡片还是最初那版，
后面新增的锐评、冲突深描、主题深描结论没有回到画像里，读者要自己跨章节拼。

**做法**：在画像 section 内加一个「据后续深描回写」小结，把每个新模块的结论压缩成两三行补进双方卡片。
合并只统一格式、不改内容；若确实改了数字，记进 `[[book.revision]]` 勘误表。

---

## 20. 分手前后写下的抒情文本，先做「对象归属核查」再解读（实测）

用户说「这是我和 A 分手后写的文章」，最自然的反应是直接按 A 去解读。**但「写作时间」不等于「怀念对象」**。

实测：一篇被归到「分手后」的小作文，文中若干专属细节（某次聚会 / 某个物件 / 某个日常片段 / 收藏的车票 / 几年后的自己），全部逐字对应**上一段关系**某一天的聊天原文；而当下这段只有约 266 天，物理上不可能出现「几年后的自己」。它还恰好是分手那场对话的引信——对方读出了「怀念」，被判成「没放下前任」，两边都只说对了一半。

**做法（三筛）**：
1. **时间锚点**：文里的日期、季节、「几年后」跨度，先和每段关系的起止对齐；跨度对不上就换段。
2. **专属名词**：每段关系有自己的物件/称呼/地点（手串、堂弟、培训 vs 连麦、寝室、车票）。做一次两段专属词命中统计，零命中的那段基本可排除。
3. **排除法 + 反查上下文**：文章在聊天里第一次「被读到」的那一刻，双方怎么说的，往往比文章本身更能定位对象与动机。

**解读也要分层**：对方的指控可能「感受层读对、对象层认错、动机层上纲」。别因为情绪读对了就全盘采信，也别因为归因错了就写成「纯属投射」。三层分开写，才不会把档案写成辩护词。

**顺带**：这类文本最能暴露「表达时机」——关系内说不出的话，常在结束后变成最漂亮的文字。写画像时单独标一节，比再加十条性格形容词有用。
